1 · Menu structure (Appearance → Menus)

Exactly 4 top-level items + 3 utility links. Second level = section hubs and collections only — individual index pages and news reports are never menu items; they live on hub-page card grids. Publishing a new page never touches this menu.

2 · Markup — what WordPress already outputs

The whole design is a restyled wp_nav_menu() nested list. No structural changes needed:

<nav aria-label="Primary">
  <ul id="primary-menu">
    <li class="menu-item-has-children">
      <a href="/indexes/">Indexes</a>
      <button class="dropdown-menu-toggle" aria-expanded="false">…</button>
      <ul class="sub-menu">   ← this becomes the dark palette
        <li><a href="/indexes/enterprise-adoption/">Enterprise AI Adoption</a></li>
        …
      </ul>
    </li>
    …
  </ul>
</nav>

Critical for LLM/crawler friendliness: every link stays in the server-rendered DOM at all times. Sub-menus hide with CSS (visibility/opacity) + aria-expanded — never lazy-loaded, never display:none-until-fetch. GeneratePress does this by default.

3 · GeneratePress settings

  • Customizer → Layout → Primary Navigation → Dropdown behaviour: "Click – arrow". Kills hover-only dropdowns; the arrow button toggles aria-expanded, the label itself still navigates to the hub page. Works identically on touch.
  • Mobile menu breakpoint: default 768px. Keep GP's off-canvas/overlay mobile menu — it renders the same nested list as accordions (Option B's bottom-sheet chrome is a nice-to-have, see §5).
  • Register a secondary menu location for Subscribe / Contact / Log in (top utility strip). Never place them in the primary menu. Log in sits last, ink-colored to separate it from the muted links; on mobile it lives in the drawer footer (Option A) / More tab (Option B sheet).

5 · Flags / can't-do-in-plain-WP

  • Bottom sheet on mobile: not a native WP menu behaviour. Ship GP's standard off-canvas overlay first (same content, accordion sub-menus — fully acceptable). The sheet + tab chrome from the prototype needs ~30 lines of custom CSS/JS on top of the same markup; treat as phase 2.
  • "Jump to a section…" search row: decorative in the prototype. A live filter requires JS; recommend dropping it or linking the row to /indexes/ until phase 2.
  • Tag eyebrows ("Collection"/"News") in Reports: WP menu items are single labels. Use the menu item Description field + CSS (.menu-item-description) — GP outputs it with a filter snippet.
  • Right-anchored flyouts can overflow on narrow desktop widths; the CSS anchors them right:0 which handles the last items — verify the Indexes item at 769–1100px.

6 · Acceptance checklist

  • All 9 sections + Compare visible in Indexes dropdown; numbering 01–09 renders via CSS, not labels.
  • Tap once on "Indexes" arrow on iPhone → palette opens; tap label → hub page. No dead first-tap.
  • View-source (JS off): every second-level link present as <a href>.
  • Keyboard: Tab reaches every item, Escape closes, aria-expanded toggles.
  • Publish a test index page → confirm nav needs no edit.
